# STM32 AGV Timer 通信协议

## 1. 协议概述

- 传输方式：USB CDC，设备作为 USB 虚拟串口连接 PC。
- 数据方向：当前只定义 MCU 到 PC 的上报数据，PC 发送到 MCU 的数据暂不处理。
- 编码：ASCII。
- 数据形式：以 `\r\n` 结尾的文本行。USB 数据包边界不等同于协议消息边界，PC 端必须自行缓存并按行解析。

## 2. 消息格式

每条消息格式如下：

```text
START,<timestamp>\r\n
END,<timestamp>\r\n
EVENT,<timestamp>\r\n
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `START` | recording 从 OFF 切换为 ON 时发送 |
| `END` | recording 从 ON 切换为 OFF 时发送 |
| `EVENT` | 检测到一次有效 AGV 到达时发送 |
| `timestamp` | 无符号十进制整数，MCU 本次上电后的单调递增毫秒数 |
| `\r\n` | 固定的消息结束符，即 CR（0x0D）+ LF（0x0A） |

消息中不包含空格、引号或其他字段。示例：

```text
START,1234\r\n
EVENT,9876\r\n
END,15321\r\n
```

`timestamp` 使用 64 位数值保存，PC 端建议使用 64 位整数解析。它不是 RTC 时间，也不是 Unix 时间；MCU 复位或重新上电后会重新从 0 开始计时。

## 3. 记录生命周期

### 3.1 状态切换

- MCU 上电后 recording 默认为 OFF，不会自动发送初始 `END`。
- PA4 按键经过 50 ms 防抖后切换 recording 状态。
- OFF → ON 时发送 `START,<timestamp>\r\n`。
- ON → OFF 时发送 `END,<timestamp>\r\n`。
- `START` 和 `END` 中的时间戳表示按键状态切换发生的 MCU 时间，不是 USB 实际发送时间。
- 如果 MCU 在 recording ON 状态下复位或断电，PC 可能收不到对应的 `END`。

### 3.2 光电事件

- 光电输入由“通光”变为“遮挡”时记录一次 `EVENT`。
- 只有 recording ON 时才捕获新的光电事件。
- recording 切换为 ON 时，如果此刻已经处于遮挡状态，不会立即生成 `EVENT`；必须等待下一次“通光 → 遮挡”边沿。
- 每次有效事件后有固定 3000 ms lockout，用于过滤同一台 AGV 的重复触发。
- recording OFF 只停止捕获新事件；已经捕获但尚未发送的事件仍会继续发送。

## 4. 发送与重复消息

- `START`、`END`、`EVENT` 共用一个容量为 64 条消息的 MCU RAM 队列。
- 正常情况下按入队顺序发送；同时待处理的状态切换和光电事件会按 MCU 时间戳顺序入队。
- 队列满时，固件会覆盖最早的消息，因此 PC 端不能把断开期间的数据完整性视为无限保证。
- USB 发送状态不确定时，固件可能重发同一条消息。PC 端必须支持重复消息。
- 推荐使用 `(message_type, timestamp)` 作为去重键。例如，`EVENT,1000` 的重复消息应忽略，但不能因为时间戳相同而误删 `START,1000` 或 `END,1000`。

## 5. PC 端解析建议

建议按以下方式处理 USB CDC 数据：

1. 将收到的字节追加到接收缓存。
2. 持续查找 `LF（0x0A）`；找到后检查前一个字节是否为 `CR（0x0D）`。
3. 去掉行结束符，按第一个逗号拆分消息类型和时间戳。
4. 消息类型必须是大写的 `START`、`END` 或 `EVENT`；时间戳必须是非负十进制整数。
5. 对合法消息先按 `(类型, 时间戳)` 去重，再根据时间戳更新记录状态和 AGV 事件。

不要依赖以下行为：

- 一次 USB `read` 恰好返回一条完整消息；
- 一条消息一定只出现在一个 USB 数据包中；
- PC 收到消息的时间等于事件发生时间；
- MCU 一定能在复位、断电或 USB 拔出前发送 `END`。

## 6. PC 端记录逻辑

- `START` 可作为一次记录会话的开始标志，并保存其 MCU 时间戳。
- `END` 可作为记录会话的结束标志，并保存其 MCU 时间戳。
- `EVENT` 的节拍计算应使用 MCU 时间戳，不要使用 PC 收包时间。
- USB 重连或检测到时间戳回退时，建议 PC 端创建新的 MCU 会话，并清理上一会话的临时状态。

## 7. 协议示例

一次完整记录可能收到：

```text
START,120000\r\n
EVENT,121532\r\n
EVENT,182104\r\n
EVENT,241876\r\n
END,300000\r\n
```

上例中，PC 可以使用 `EVENT` 时间戳计算 AGV 到达间隔；`START` 和 `END` 用于界定本次记录会话。
